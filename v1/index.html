RCMF (Roblox Community Modding Format) Version 1

Abstract

This document specifies version 1 of the RCMF (Roblox Community Modding Format) file format. RCMF is a JSON-based file format used to define and package modifications for the Roblox client. It allows defining rules for modifying files, asset types, and specific asset IDs.

1. Introduction

The Roblox Community Modding Format (RCMF) is designed to streamline the process of modifying the Roblox client. By defining changes as a declarative set of rules serialized into a JSON configuration format, mod developers can reliably distribute modifications to files on disk, Roblox asset IDs, and entire asset types.

2. Terminology

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in RFC 2119.

3. File Format Structure

An RCMF file is a well-formed JSON document containing a single serialized root object.

3.1. Root Object

The root object of an RCMF file.

  • spec (string): REQUIRED. Defines the RCMF specification version used. It MUST be a link to a document describing the spec. For this version, it MUST be set to "https://rcmf.axell.me/v1".
  • rules (array of rule objects): REQUIRED. An array that describes the modification rules of this mod.

3.2. Rule Object

Rules describe what to modify or replace (sources) and what should be changed (data).

  • sources (sources object): REQUIRED. Describes the sources that this rule applies to.
  • data (data object): REQUIRED. Describes the data used to replace or modify the matched sources.

3.3. Sources Object

Describes what a rule should modify or replace. A rule may target multiple sources of multiple different types.

  • expressions (array of strings): OPTIONAL. Reserved for future use. Implementations SHOULD ignore this field.
  • ids (array of integers): OPTIONAL. A list of Roblox asset IDs to modify.
  • types (array of integers): OPTIONAL. A list of asset types to modify, represented as asset type IDs.
  • files (array of strings): OPTIONAL. A list of files on disk to modify. These paths are relative to the Roblox installation directory (e.g., C:\Users\ms\AppData\Local\Roblox\Versions\version-ec412128eba3476e).

3.4. Data Object

Describes what a rule should replace its sources with, or how to modify its sources.

  • blob (string, base64-encoded bytes): OPTIONAL. Represents a binary object to completely replace the targeted sources.
  • key (string): OPTIONAL. Describes a specific part of an XML or JSON document to modify. If the target is an XML document, "key" MUST be an XPath expression. If the target is a JSON document, "key" MUST be a dot-separated path. This field SHOULD be empty when "blob" is set.
  • value (string): OPTIONAL. Describes the value to set the target defined by "key" to. It MUST be present if "key" is utilized to modify a document.
